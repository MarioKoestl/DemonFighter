# Asset Pipeline

Nobody on this project models in Blender, and Claude Code cannot create 3D models or textures. The plan is built around that: shapes come from generators. Rigging and animation are done in Blender from M6 on (D-100): Mario animates, Blender Python scripts by Claude Code do the repetitive work, and `docs/BLENDER_GUIDE.md` teaches the steps.

For the click-by-click version (accounts, tools, prompts, Audacity, Unity steps, license entries), read `ASSET_GUIDE.md`.

## Stages

1. **Primitives (M0 to M4).** Capsules, spheres and cubes with flat colors. Color encodes tier, size encodes mass. Everything about gameplay is built and tested on these. Nothing in the code may depend on a specific mesh.
2. **AI-generated assets (M5).** Text-to-3D and image-to-3D tools produce meshes and PBR textures for the core blob and each body part. Expect cleanup work.
3. **Polish (M6 and later).** Commissioned or purchased assets for anything the generated ones cannot deliver. Asset Store packs for gore, VFX and audio.

## Placeholder standard (stage 1)

- Core: capsule, 1.2 m tall for Tier 0. Scale with tier.
- Parts: cubes or stretched capsules attached to socket transforms. Arm: 0.6 m box. Legs: two 0.5 m capsules. Hide: a slightly larger transparent shell.
- Colors: player a fixed teal; AI demons by tier (0 gray, 1 olive, 2 rust, 3 dark red, elders near black).
- Damage: wounded part darkens and shrinks to 80 percent; severed part detaches with its own collider and rigidbody.
- Blood: a flat round decal, two sizes.

All placeholder assets are generated by the `Demon Fighter > Generate > Placeholder Assets` menu so they can be regenerated after changes.

## AI-generated 3D assets (stage 2)

Candidate tools, as of late 2026 (check current terms before use; they change often): Meshy, Tripo, Rodin (Hyper3D), Luma Genie. Also Unity's own AI features inside the editor. Mario tries two or three with the same prompt and picks by result quality and license.

Workflow per asset:

1. Write a short brief in `docs/briefs/<asset>.md` (versioned, D-079; `docs/briefs/README.md` has the conventions, and the first five briefs are there): what the part is, which socket, approximate size, pivot and axes, the damage states, style reference words (wet, veined, chitin, raw muscle). Keep reference images in `ArtSource/`.
2. Generate. Export FBX with PBR textures (base color, normal, roughness, metallic). Unity has no built-in GLB importer; GLB would need the glTFast package, a dependency we have not taken (D-079).
3. Check: triangle count within budget, textures at the target resolution, the pivot at the attachment point, forward axis +Z, up axis +Y, scale in meters.
4. If the tool offers retopology or decimation, use it. If the result is a mess, try another generation before trying to fix it.
5. Drop the files into `Assets/_Project/Art/Models/<Category>/` (`Core`, `BodyParts`, `Elders`, `World`). `ArtImportRules` applies the import settings below as the files are imported; nothing to click.
6. Record the asset in `docs/ASSET_LICENSES.md`: tool, date, plan, license terms, commercial use allowed yes or no, link to the terms.
7. Keep the source files (raw exports, textures, prompt, seed) in `ArtSource/` next to the repository on Mario's PC. `ArtSource/` is gitignored for now because GitHub Free has LFS quotas (see `DECISIONS.md` D-021). Back it up separately.
8. Run `Demon Fighter > Generate > Placeholder Assets` (or `Demon Fighter > Art > Bind Art Assets`): `ArtAssetBinder` points every part asset at the meshes that carry its name, so nobody drags meshes into Inspectors.
9. Run `Demon Fighter > Art > Validate Art Assets`: naming, triangle and texture budgets, damage states, sockets, scale, pivot and the license entries. The report goes to the Console and to `TestResults/art-validation.txt`. Errors mean the asset cannot ship as it is.

Known limitations to plan for: generated meshes have messy topology and rarely deform well. That is fine for a blob and for rigid parts (jaws, plates, spines). For arms and legs expect to either accept stiff animation or use procedural animation (see below). Modular parts need a consistent scale; always generate with the core model's size as the reference.

## Modular body parts

- One mesh per part, modeled standing upright on the end that touches the body. The binder puts the pivot at the bottom center of the model as it stood in the tool, and the Euler knob turns it from upright into place (D-088).
- Naming: `BP_<Part>[_<Variant>]` for the model, matching the ScriptableObject id `part.<part>[.<variant>]`: `BP_Jaws` is `part.jaws`, `BP_Hide_Thick` is `part.hide.thick`. The binder reads the name.
- Each part ships with damage states as separate files (`BP_Arm_Intact.fbx`, `BP_Arm_Wounded.fbx`, `BP_Arm_Mangled.fbx`, and `BP_Arm_Stump.fbx` for the body-side remainder after severing) or as child objects named by state inside one file. Generated as variants of the same prompt, or by editing in a mesh tool if someone learns one. A missing state falls back to the next healthier one; a lost part without a stump vanishes. The view picks the stage from the HP fraction of the part (`DemonViewSettings`, D-080): wounded below 50 percent, mangled below 20, stump when lost.
- Socket positions are empty transforms on the core model named `Socket_Head`, `Socket_LimbL`, `Socket_LimbR`, `Socket_Locomotion`, `Socket_Hide`, `Socket_Tail`, each with its +Z pointing away from the body. The binder converts them into anchors in body units (origin at the base, 1 is the body height) on the core asset (`Visual > Anchors`); `DemonFigure` hangs mesh parts on them and scales the rig with the body. A core without sockets keeps the anchors of the placeholder capsule, tunable in the Inspector. Every part asset carries three fit knobs (`Visual > Meshes > Scale`, `Offset`, `Euler`) on top of an import fix, which the binder works out on every bind (D-088): the turn and unit scale the model file carries on its own object, the size that makes the model's longest side 1, and the pivot at the bottom center of the model as it stood in the tool. The knobs start neutral and mean "relative to how the model looked in the tool that made it": Scale is the longest side in body heights, Euler turns the part around its pivot, and Offset moves it along its socket (+Z out of the body, +Y up). A copy on the left flank of a part that mirrors its second copy (the arm) takes the knobs mirrored. The binder never overwrites the knobs after the first bind.

## Animation

- Everything is procedural in M5 (D-082, `BodyAnimator`): the body breathes, stretches along its run, bobs with its gait, swells and nods on a bite, stretches on a lunge, shakes when hit and throbs through a transformation; legs step, limbs swing and strike, jaws open and snap, tails sway and whip. No clips, no rigs. A generated mesh only needs its pivot at the socket; the motion turns it around that pivot.
- What moves how is data: `Motion` on the part asset (`Visual > Motion`: Legs, Limb, Jaws, Tail or None) and `Motion` on the skill asset (`Look > Motion`: Bite, Swipe, Lunge, Tail Swing or None). Amplitudes and timings of the motion are in `DemonViewSettings.asset` under `Motion`.
- Clip slot: a part may carry a hand-made clip (`Visual > Meshes > Clip`). Import the file under `Assets/_Project/Art/Animations/`; the import rules mark it as a legacy clip, the view plays it in a loop on that part and the animator leaves the part alone. Mixamo does not fit a modular blob (humanoid rigs), so it is not planned.
- Attack timing (active frames of hitboxes) is data on the skill, not baked into clips, so placeholder and real bodies strike on the same numbers; the animator reads windup, active and recovery from the skill.

## Gore assets

- Blood: decal textures (splats, pools) at 1024 px, used with URP Decal Projector (`BloodDecalPool`). Until real ones exist, `TextureGenerator` paints placeholders into `Assets/_Project/Art/Textures/Decals/Generated/` (`T_Blood_Splat_01` to `03`, `T_Blood_Pool`); a hand-made PNG dropped under the same name replaces the painted one on the next generate. The decal materials live in `Assets/_Project/Art/Materials/Decals/`.
- Size range: every body asset must read well from 1 meter to 15 meters, so textures use tiling detail rather than a single baked resolution, and parts come in the same proportions at every size step (the view scales them).
- Viscera: a handful of small generic meshes (strands, lumps) spawned on severing and death, pooled (`VisceraPool`). `VisceraMeshes` builds placeholders from code; real meshes come through the pipeline later.
- Wound shader: `DemonFighter/DemonSkin` (HLSL, `Assets/_Project/Art/Shaders`), URP Lit with a blood mask that darkens and wets the surface around the last wound and streaks down the body. Every demon material uses it; a bound part material is switched to it by the generator, keeping its textures, because the properties match Lit.
- Asset Store gore and blood packs are allowed; license note required.

## Audio

Sounds are `AudioEventDefinition` assets under `Assets/_Project/Content/Audio/` (`AE_<Name>`), each with its clips, volume, pitch, distances and cooldown (D-084). Clips live under `Assets/_Project/Audio/`; `AudioImportRules` imports them as Vorbis, effects (`S_`) mono and decompressed on load, loops (`L_`) and music (`M_`) streaming. Until real clips exist, `AudioSynth` writes placeholder WAVs into `Assets/_Project/Audio/Generated/` on the first generate; a WAV, OGG or MP3 dropped under the same name replaces the synthesized one on the next generate, or drop any file and assign it in the event asset. Sources for real effects: AI sound tools or CC0 libraries, each with an entry in `docs/ASSET_LICENSES.md`.

## Music

AI-generated. Candidate tools change quickly; Mario picks one, checks that the terms allow commercial use in a game, and records each track in `docs/ASSET_LICENSES.md` with prompt, tool, date and terms. Keep stems or at least the raw export in `ArtSource/music/`. Three tracks are needed for v1: menu, calm and combat, as seamless loops; the generator's `M_Menu_Placeholder`, `M_Calm_Placeholder` and `M_Combat_Placeholder` under `Assets/_Project/Audio/Generated/` are stand-ins to replace under the same names (then assign them in `AudioCatalog.asset` and `BI_AshCavern.asset` if the names differ).

## Budgets (v1)

| Asset | Triangles | Textures |
|---|---|---|
| Core blob | 8k | 2048 set |
| Body part | 2k to 5k | 1024 set |
| Elder (whole) | 40k | 4096 set |
| World feature | 1k to 3k | 1024 or atlas |

The validator reports a model over its folder budget as an error. Every demon body carries an `LODGroup` with two levels (D-083): below 4 percent of the screen height the parts drop and the core draws alone, below 0.6 percent nothing draws; real LOD meshes per part are not planned before a run shows more than 30 demons on screen.

## World surfaces

Until real textures exist, `TextureGenerator` paints tileable surfaces into `Assets/_Project/Art/Textures/Surfaces/Generated/`: `T_Ground`, `T_Rock`, `T_Wall` and `T_Lava`, each as `_BaseColor` and `_Normal`, lava also `_Emission` (D-083). The world materials in `Art/Materials/Placeholder` use them with a tiling per shape (ground every 4 m through the terrain UVs, rocks and walls per face). A hand-made PNG dropped under the same name replaces the painted one on the next generate; a different tiling is a change on the material.

A base color texture is albedo, the share of light the surface reflects, not how dark it should look in the game. Ash and volcanic rock reflect about a tenth of the light: in the image their pixels average roughly 80 to 100 of 255, with no large areas below 40. The cave gets its darkness from the lighting; a near-black texture leaves the light nothing to show (D-087). The same goes for demon textures: red flesh around 110 to 150 of 255 in its brightest channel keeps the side away from the light readable; the first core texture averages 65 in red and renders as a dark shape on its shadow side.

## Import settings

Enforced by `ArtImportRules` (an `AssetPostprocessor`) for everything under `Assets/_Project/Art/`; the list is what it sets.

- Models: scale factor 1, read/write off (on under `BodyParts`, so the view can mirror a part for the left flank, D-088), generate colliders off (we add our own), mesh compression off under `Core`, `BodyParts` and `Elders`, medium under `World`; materials extracted into a `Materials` folder next to the model; cameras, lights, blend shapes and animation import off (bodies animate procedurally).
- Textures: sRGB for base color only; normal maps marked as normal; max size per the budget table; compression BC7 for color, BC5 for normals. The name decides the kind: `normal`, `_nrm`, `_nor`, `_n` is a normal map; `rough`, `metal`, `_ao`, `occlusion`, `orm`, `mask`, `height`, `displace`, `smooth`, `gloss` is linear data; everything else is base color.
- Animation clips: loop time set for locomotion, root motion off (code drives movement).

## Licensing log

`docs/ASSET_LICENSES.md` holds one entry per asset or pack:

```
## <asset or pack name>
- Source: <tool, store, or person>
- Date: YYYY-MM-DD
- License: <name and link>
- Commercial use: yes / no / with attribution
- Attribution text (if required): ...
- Files: Assets/_Project/Art/...
```

Nothing ships without an entry. This is what Steam and a publisher will ask about.
